# UI: 納品ポータル（#5 [delivery.md](delivery.md) の画面設計）

> ステータス: **本サブシステムは別リポ ICS-DELIVERY（`~/icstv-delivery`、Node/TS・別 Postgres）へ完全移管済み**（2026-07、Phase 3.9 Stage G/H）。**本書は歴史的記録**であり、ここに描かれた画面は ICS-TV には存在しない（現行 UI は ICS-DELIVERY リポジトリ側）。ICS-TV に残るのは内部 seam（`/api/v1/internal/delivery-asset`・`/api/v1/internal/delivery-refs`）と ghost app `server/delivery` のみ。詳細は [delivery.md](delivery.md) 冒頭のステータスを参照。
>
> ICS-TV の UI 仕様は [ui.md](ui.md) を全体の出所（IA・共通シェル・視覚言語）とし、
> 本書はそのサブセットとして #5 納品ポータルの画面を定義していた。視覚言語・記号体系は ui.md に従う。

本書は #5 納品ポータル（[delivery.md](delivery.md)）の画面群を ASCII ワイヤーフレームとして定義する。視覚言語・シェル・記号体系は [ui.md](ui.md)（素材・CM 管理の CRUD 体裁）に統一する。社内シェルは納品ダッシュボード／作成・QC・番販・組織管理を担い、外部制作会社は社内ナビを持たない軽量ポータル（組織スコープ・行レベル RBAC）を別シェルで提供する。各フィールド名はモデルの正式名（`delivery` / `delivery_file` / `qc_report` / `production_company` / `delivery_account`）に対応づける。

状態機械（`delivery_file` 単位）と承認後の purpose 分岐（D2）は delivery.md に従う。状態バッジは `delivery_status` を、QC 判定は `qc_verdict`（ok/warn/ng）を用いる。

> 権限について〔歴史的記述〕: 各画面の「対象ロール」は ui.md 旧ロール表の社内ロール（Django グループ）と `delivery_account.role` の 2 層 AND 合成で定める設計だった（delivery.md「2 層の権限合成（社内ユーザ）」）。**この合成は ICS-TV では実装されないまま移管された**（ICS-TV の管理権限は `is_superuser`/`is_staff` の 2 値のみ）。現行の納品 RBAC は ICS-DELIVERY の所管。

## 1. 納品ダッシュボード（program × purpose マトリクス）

対象ロール: 全内部ロール（管理者 / 運用者 / 営業 / 経理 / QC担当）が参照（社内グループ ＋ `delivery_account.role` が internal_* の AND 合成）。外部ユーザは画面 9（自社一覧）へ。サブナビ「納品」配下。マトリクスの各セルは当該 `(program, purpose)` の現行 `delivery_file`（最大 version）の `status` をバッジ表示する。セル押下で当該 delivery_file の詳細／プレビュー／QC へドリルダウンする。

├──────────────────────────────────────────────────────────────────────────────────────────────┤

├──────────────────────┬──────────┬──────────────┬──────────┬──────────┬──────────┬─────────────┤

- 行 = `delivery.program_id`（`program.title` 表示）＋ `delivery.company_id`（社内=NULL を「社内」、それ以外は `production_company.name`）。`program_id=NULL` の単発 delivery は別ブロックへ集約。

- 会社フィルタは `delivery.company_id`。`◐` バッジ（◐up/◐qc）を含む行が 1 つでもある間のみ `<tbody>` を 2s ポーリング。

## 2. 納品作成 → アップロード（presigned マルチパート）

対象ロール: 社内納品の作成は operator-shell 作成権を持つ社内ユーザ（管理者 / 運用者 / 営業 の Django グループ ＋ `delivery_account.role` internal_* の AND 合成）。外部は画面 9。`delivery`（ヘッダ）を起こし、用途ごとに `delivery_file` を追加 → サーバが presigned マルチパート URL を払い出し → ブラウザ分割 PUT（進捗・レジューム）→ 完了通知で `upload_state=complete`・`run_qc.delay()`。

- 進捗 = presigned マルチパート PUT の累積。size=`size_bytes`、checksum=`checksum`（client SHA256 → 完了時サーバ再計算で照合）、r2_key=`r2_key`（quarantine）。完了で `upload_state=complete`・`status=uploaded` → `run_qc.delay(delivery_file_id)` → `qc_processing`。
- レジューム=マルチパート既存パートの継続。aborted は `upload_state=aborted`。

## 4. QC レビュー（QC担当 / 管理者）

対象ロール: 人手 verdict・コメント入力は QC担当（Django グループ）＋ `delivery_account.role=internal_qc` の AND。承認（approved）→ Asset 化（`intended_kind=program` のみ）は管理者（＝`delivery_account.role=internal_admin` を持つ社内ユーザ）。自動 QC 結果（ffprobe 技術 / ラウドネス I・LRA・True Peak / リーダー検出 warn）を表示し、人手 `human_verdict`（ok/warn/ng）＋ `comment` を入力する。`qc_failed`（自動 NG）は承認不可。

```
┌─ 納品 ▸ QC レビュー（delivery_file #882 / 夜のニュース 6/11 / broadcast / v1） ───────────────┐
│ 納品 ▸ QC レビュー   夜のニュース 6/11 / broadcast / v1     status: ◧qc_ok（人手QC待ち）      │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│ 自動QC（run_qc / qc キュー）           auto_verdict: ▲warn      [ ▷ プレビュー ]              │
│ ┌─ 技術チェック（ffprobe / auto_result）───────────────────────────────────────────────────┐ │
│ │ 解像度/fps : 1920×1080 / 29.97  ●OK（規定 1080/29.97 と一致）                            │ │
│ │ 尺         : 00:28:30  ●OK（尺ゼロでない）                                               │ │
│ │ コーデック : v=h264 / a=aac  ●OK   音声トラック: 有り ●OK                                │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────┘ │
│ ┌─ ラウドネス（ebur128 実測 / qc_report）──────────────────────────────────────────────────┐ │
│ │ loudness_i (Integrated): -16.2 LUFS   目標 -14±1 → |Δ|=2.2 ▲warn                         │ │
│ │ loudness_lra            :  9.4 LU                                                        │ │
│ │ true_peak               : -1.1 dBTP   目標 ≤ -1.5 → ▲warn（mezzanine loudnorm で吸収）   │ │
│ │ ※ラウドネスは測定・警告のみ（D4）。レベル統一は mezzanine 側 loudnorm 2-pass で機械保証  │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────┘ │
│ ┌─ リーダー検出（D6 / blackdetect・silencedetect・1kHz トーン）───────────────────────────┐ │
│ │ 冒頭黒み: 0.0–1.8s 検出  / 冒頭無音: 0.0–2.0s  / 1kHz トーン: 検出  → ▲warn               │ │
│ │ ⚠ 頭に校正リーダー（バー/黒/トーン）混入の疑い。視覚的バー色判定は Phase B               │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│ 人手QC（reviewer=ログイン auth_user）                                                         │
│ human_verdict:  ( ○ ●ok )  ( ○ ▲warn )  ( ○ ✕ng )       現在: ○未レビュー                    │
│ comment: [ 頭の校正リーダーは送出時にカットされる前提。ラウドネスは mezzanine で吸収。   ]   │
│          [                                                                              ]   │
│ [ verdict を保存（reviewed_at 記録） ]                                                        │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│ 承認（管理者のみ・intended_kind=program → Asset 化）                                          │
│ [ ✕ 差し戻す（rejected）… ]◆要確認        [ ● 承認（approved）→ Asset 生成 ]◆要確認          │
│  └ 差戻し理由を制作へ通知                  └ asset(kind=program) 生成→normalize→R2 mezzanine  │
│ ※auto_verdict=ng（qc_failed）の場合: 承認ボタンは (無効・自動QC NG)。再納品で差し戻しのみ     │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

注記:
- 自動結果 = `qc_report.auto_result`（jsonb: ffprobe/ebur128/black/silence/tone の生結果）、総合 = `qc_report.auto_verdict`（ok/warn/ng）。技術不適合・尺ゼロ・音声無しは ng（承認ブロック）、ラウドネス外れ・リーダー疑いは warn。
- ラウドネス = `qc_report.loudness_i`（Integrated LUFS 原音実測）/ `loudness_lra` / `true_peak`（dBTP 原音実測）。目標 -14 LUFS±1 / TP ≤ -1.5（D5）。測定・可視化のみ、統一は mezzanine（D4）。
- 人手 = `qc_report.human_verdict`（NULL=未レビュー）/ `comment` / `reviewer_id`（=ログイン `auth_user`）/ `reviewed_at`。`status=qc_passed`（auto ok|warn）でのみ人手 verdict 可。
- 承認 = `delivery_file.status → approved`。`intended_kind=program` のとき `asset(kind=program)` 生成 → `delivery_file.asset_id` 紐付け → 既存 normalize → R2 mezzanine（D2）。`auto_verdict=ng`（`qc_failed`）は承認不可、差し戻し（rejected）のみ。差戻し→再納品で新 version の delivery_file が `uploading` から。
